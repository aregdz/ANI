# API и маршруты проекта

Проект «А.Н.И — Живая Карта Истории» реализован как Django-веб-приложение. Основное взаимодействие пользователя с системой выполняется через серверные маршруты, которые обрабатывают регистрацию, авторизацию, добавление историй, просмотр материалов, отзывы и административные действия.

## Основные маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/` | Главная страница с интерактивной картой и опубликованными историями |
| GET / POST | `/register/` | Регистрация нового пользователя |
| GET | `/verify-email/<uidb64>/<token>/` | Подтверждение email пользователя |
| GET / POST | `/login/` | Вход пользователя в систему |
| GET | `/logout/` | Выход пользователя из системы |
| GET / POST | `/password-reset/` | Запрос восстановления пароля |
| GET | `/password-reset/done/` | Страница успешной отправки письма восстановления |
| GET / POST | `/reset/<uidb64>/<token>/` | Установка нового пароля |
| GET | `/reset/done/` | Страница успешного изменения пароля |
| GET / POST | `/stories/add/` | Добавление новой истории |
| GET | `/stories/my/` | Просмотр историй текущего пользователя |
| GET / POST | `/stories/<id>/` | Просмотр истории и добавление отзыва |
| GET | `/admin-panel/` | Панель администратора |
| GET / POST | `/admin-panel/stories/<id>/edit/` | Редактирование истории администратором |
| GET | `/admin-panel/stories/<id>/publish/` | Публикация истории администратором |
| GET | `/admin-panel/stories/<id>/delete/` | Удаление истории администратором |
| GET | `/admin-panel/users/<id>/delete/` | Удаление пользователя |
| GET | `/admin-panel/users/<id>/stories/` | Просмотр историй конкретного пользователя |
| GET | `/admin-panel/stories/<id>/reviews/` | Просмотр отзывов к истории |
| GET | `/admin-panel/reviews/<id>/delete/` | Удаление отзыва |

## Примечание

Проект использует серверную архитектуру Django. Данные передаются через HTML-формы, а обработка выполняется на стороне backend-части приложения. Отдельный REST API в текущей версии не реализован, однако маршруты проекта выполняют роль серверных точек взаимодействия между пользовательским интерфейсом и backend-логикой.
